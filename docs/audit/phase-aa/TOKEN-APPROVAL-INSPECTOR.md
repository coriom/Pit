# Phase AA — Token Approval Inspector

**Result:** A separate, read-only `/tools/token-approvals/` utility is available in the PIT toolbox. It accepts a public EVM address without a wallet connection, reads Ethereum Sepolia only, and never signs, approves, revokes or submits a transaction. Ordinary `FEES_ENABLED=false`, `MAINNET_ENABLED=false` and `UNISWAP_EXECUTION_ACCEPTED=false` remain unchanged. All pages remain noindex. Assumption 8 and legal/mainnet gates remain OPEN.

## Exact product scope

The inspector reads only Circle test USDC (`0x1c7D4B196Cb0C7B01d743Fbc6116a902379C7238`) and Sepolia WETH (`0xfff9976782d46cc05630d1f6ebab18b2324d6b14`), paired with Uniswap SwapRouter02 (`0x3bFA4769FB09eefC5a80d6E87c3B9C650f7Ae48E`) and the CoW relayer (`0xC92E8bdf79f0507f65a392b0ab4667716BFE0110`). The four cross-product allowance calls use `allowance(owner,spender)` through viem at one pinned block, with ERC-20 `balanceOf`, exact decimals 6/18 and code-presence checks. Wrong chain or a stale source block rejects the report. A failed individual code, decimals, balance or allowance read is shown as unavailable rather than zero; other supported rows remain usable.

The page shows full token/spender identities, allowance as an exact integer and decimal string, token balance separately, block and observation times, and Sepolia explorer links. It explicitly says that zero across these four pairs **does not prove there are no other approvals**. An allowance is spending capacity, not evidence that tokens were transferred or stolen; it can remain after a stopped transaction attempt. The browser generates a local JSON file containing the reviewed identities, exact raw amounts, verified decimals, block, timestamp and limitation. No Taxlot schema, IndexedDB store, backend, address analytics or approval-indexer API is involved.

## Deterministic and browser evidence

Unit cases cover invalid address, wrong chain, exact/zero/uint256-sized allowance, wrong decimals, mismatched spender identity, missing token and spender bytecode, timeout/partial failure, stale and future blocks, balance failure, fixed-pair coverage and JSON export fidelity. Browser cases cover public-address entry, exact displayed allowance, actual local JSON download, wrong-chain and partial RPC responses, keyboard operation and narrow-screen layout. The browser fixture counted zero wallet-provider requests, zero IndexedDB opens, and no `eth_sendTransaction`, `eth_sendRawTransaction` or signing RPC method. Only the local static page and the reviewed Sepolia RPC were contacted. These are mocked-RPC tests, not additional live on-chain actions.

The first targeted Playwright run passed 3/4: one test wrongly searched for the always-visible coverage notice *inside* the conditional result container. The page had rendered it correctly outside. After correcting that test locator, the confirmation run passed 4/4. The initial unprivileged browser invocation could not launch the local preview server under sandbox process/network limits; rerunning with permitted local loopback access resolved that environmental block. No production defect or transaction was involved.
