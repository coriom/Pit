# Phase AD — Portfolio Exposure Analyzer

`/tools/portfolio-exposure/` is a registry-driven, browser-local analysis of **manually supplied long-only spot holdings**. It does not discover wallets, read RPC or prices, execute trades, persist holdings, or infer tax lots from transaction history. The Ethereum, Base and Arbitrum chain names, including mainnet IDs, are descriptive offline identifiers only. `FEES_ENABLED=false`, `MAINNET_ENABLED=false` and `UNISWAP_EXECUTION_ACCEPTED=false` remain unchanged. Assumption 8 remains **OPEN**; this local calculation does not resolve legacy accounting recovery, public storage acceptance or legal/mainnet restrictions.

## Identity, input and coverage

Each position includes an account label, supported chain ID (`1`, `8453`, `42161`, `11155111`, `84532`, `421614`), native/ERC-20 type, a nonzero 20-byte ERC-20 address where applicable, display-only ticker, decimals (0–36 for ERC-20; 18 for supported EVM native assets), exact positive quantity, optional manually supplied USD unit price, its ISO 8601 timestamp with timezone, and optional explicit exposure group. A price and timestamp are supplied together; no price remains **UNKNOWN**, never zero. Account label plus chain-scoped asset identity (`chainId:assetType:address-or-native`) must be unique. Conflicting decimals or manual prices for the same asset stop aggregation. Matching tickers never merge assets. ETH and WETH join the same exposure group only when the user explicitly assigns it. No USDC peg or ETH/WETH equivalence is inferred.

CSV uses UTF-8, RFC 4180-style quoted fields, CRLF or LF, and this fixed header:

```text
accountLabel,chainId,assetType,tokenAddress,symbol,decimals,quantity,unitPriceUsd,priceObservedAt,exposureGroup
```

Import is capped at 256 KiB and 200 rows; the in-memory portfolio is capped at 200 positions. The page previews valid rows, displays numbered validation errors, and requires an explicit **Accept valid preview** click. Any malformed row, duplicate, conflicting price/decimals, or size violation blocks acceptance. Imported cells are rendered with `textContent`; formulas, links and macros are never executed. Manual entries and accepted CSV rows stay in page memory only. Remove and reset affect only that page state, not Taxlot or other IndexedDB stores.

## Exact valuation and concentration

`quantityRaw = quantity × 10^tokenDecimals` and `priceRaw = USD price × 10^18` are parsed as bounded decimal strings into `BigInt`, without floating-point monetary intermediates. Each known `valueUsdRaw = roundHalfUp(quantityRaw × priceRaw / 10^tokenDecimals)`. Sum per-position raw values for the **known subtotal**. Identity, chain, account and explicitly assigned group aggregations sum those same raw values. A positive unpriced holding makes full valuation **INCOMPLETE**; the known subtotal remains visible, but whole-portfolio weights, largest/top-three concentration and HHI are withheld. An empty input is **EMPTY**, never a completed portfolio. Stale prices are flagged using the user-selected whole-day threshold against their manual timestamp; they are not silently refreshed or excluded from the known subtotal.

When every holding is priced and the total is positive, `weightPpm = roundHalfUp(valueRaw × 1,000,000 / totalRaw)`; the UI renders `weightPpm / 10,000` percent with four decimals. Largest and top-three use the largest individual position raw values. `hhiMicro = roundHalfUp(10,000 × 1,000,000 × Σ(valueRaw²) / totalRaw²)` on the standard 0–10,000 HHI scale. HHI is a mathematical concentration measure, not a forecast, validated portfolio risk score or advice. If all known valuations round to zero at 10^-18 USD, percentages and HHI remain unavailable. The local JSON report preserves raw integers, input assumptions, timestamps, coverage, allocations and the manual-data disclaimer.

## Independently checked illustrative holdings

[Python `Decimal`/rational arithmetic](independent-examples.txt), separate from PIT's engine, confirms: one Ethereum native ETH at manual $2,000 is $2,000; 500 Base illustrative USDC at manual $1 is $500; 0.25 Arbitrum illustrative WETH at manual $2,000 is $500. Total is $3,000 (`3000000000000000000000` raw USD). Ethereum/Base/Arbitrum chain values are $2,000/$500/$500. Explicit ETH group value is $2,500 (`2500000000000000000000` raw), weight 83.3333%; largest position 66.6667%; top-three 100%; HHI exactly 5000. The sample ERC-20 addresses are fictional placeholders and do not imply any issuance or peg. Adding one unpriced positive holding retains a **$3,000 known subtotal** but removes whole-portfolio percentages and HHI.

## Security, privacy and limits

The inline browser bundle has an exact generated CSP hash and contains no wallet, RPC, execution or storage adapter. Browser tests block all external requests, spy on wallet calls and IndexedDB opens, verify a real local JSON download, and cover mobile and keyboard use. Release artifact checks enforce noindex and no unexpected executable remote script. No user portfolio data enters a URL, backend, cookie, analytics endpoint or persistent browser store. This V1 excludes lending debt, leveraged derivatives, LP positions, staked-token decomposition, collateral reuse, live price changes and automatic account discovery. Values and timestamps are unverified manual assumptions; results are not investment advice.

Initial targeted unit tests failed three CSV cases because their synthetic timestamp was later than the runner's actual UTC clock; the parser was given an injectable observation time for deterministic tests, while the browser continues to use its current clock. An initial local typecheck caught 20 errors around an inferred optional-map return and one unused-import hint; both were corrected. A later targeted unit run had one fixture failure after enforcing 18 decimals for supported native assets; its precision example was correctly changed to an ERC-20 position.
