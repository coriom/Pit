# Protected read-only beta hosted QA — pending

Use this checklist only after a separate approval creates a new Vercel project and deploys the exact reviewed host package. Record sanitized evidence; do not use a bypass secret, share link, wallet profile or the existing testnet staging project. A local build or READY deployment cannot satisfy these HTTP/browser checks.

1. Confirm new project ID, exact source commit, deployment ID, project root, `outputDirectory=public`, actual uploaded file list and package SHA-256. Check the project has no Git connection, environment secrets, integrations, functions, redirects or rewrites. Check all deployment URLs including any proposed alias are protected by Vercel Authentication. Query an anonymous URL: it must be denied or sent to SSO, never serve PIT.
2. In an authorized browser, confirm the final origin is the approved dedicated HTTPS hostname, its certificate is valid, and no redirect reaches `pit-testnet-staging-corioms-projects.vercel.app`. Do not print cookies or authentication headers.
3. Record actual HTTP status and public response headers for `/`, `/tools/`, all six allowlisted tools, `/robots.txt` and the CSS asset. Require 200 on the 10 served files. Require actual 404 on `/tools/swap/`, `/tools/perps/`, `/tools/wallet/`, `/tools/taxlot-export/`, `/api/` and an arbitrary unknown path; an SSO response is not a 404. Any fallback rewrite is a failure.
4. Require the response CSP on pages and CSS to match the reviewed `vercel.json` header: `connect-src 'none'`, `default-src 'none'`, exact script-hash coverage for all served inline executable scripts and `frame-ancestors 'none'`. Record HSTS without `includeSubDomains` or `preload`, `nosniff`, `no-referrer`, `DENY`, `noindex`, restrictive Permissions-Policy, and disallow-all robots. Verify response headers, not only CSP meta or local files.
5. In isolated Chromium and Firefox sessions, navigate directly to all three flagship tools. Try the illustrative portfolio, swap-cost and impermanent-loss examples; verify expected values and incomplete valuation messaging. Import a synthetic portfolio CSV, preview it before accepting, and download the local JSON report. Check mobile width, keyboard navigation, focus order and downloads. Keep Safari/mobile-device behavior **PENDING** until manually checked.
6. Inspect browser network requests and runtime APIs. Require zero unexpected remote scripts, telemetry, wallet requests, RPC/quote calls or submissions. Verify portfolio CSV contents and numeric calculation inputs are absent from requests; normal page/asset request metadata to the host is expected. Confirm no PIT Taxlot IndexedDB namespace is opened.
7. Record PASS/FAIL/BLOCKED/NOT VERIFIED per check, actual deployment ID, browser versions and any discrepancies. Stop the pilot on a security failure. After QA, remove the QA deployment/project or revoke per-user access if the pilot is not approved; verify the hostname no longer serves the site. Do not enable indexing or send tester invitations as part of QA.
