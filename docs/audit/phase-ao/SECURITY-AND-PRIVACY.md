# Phase AO security, privacy and numeric hardening

No wallet, RPC, transaction, Vercel or hosted configuration was used or changed. The complete full application remains testnet gated: `FEES_ENABLED=false`, `MAINNET_ENABLED=false`, ordinary `UNISWAP_EXECUTION_ACCEPTED=false`. Taxlot schemas/records and the protected deployed beta are untouched.

## Concentrated-liquidity numerical finding

The Phase AM continuous-range model uses 18-decimal BigInt square roots. The root floor itself is less than 10^-18 in square-root-price units, but this **did not** bound output error. An independent Python `decimal` reference at 110-digit precision found a concrete misleading case: lower/upper prices 100000000000/100000000001, initial 100000000000.5, future at lower, both token precisions six, budgets 1000 each. A sub-raw-unit token0 position could be worth nearly 2000 token1 units continuously, while raw-unit flooring reported zero. This is a real numerical defect, not merely display rounding.

The v1 engine now rejects square-root range spans below 10^-9 and rejects initial or scenario composition when one active token's smallest unit exceeds 0.01% of modeled token1 value, or when modeled value rounds to zero. This is an explicit narrower supported domain; the continuous formulas and versioned output meanings remain unchanged. The UI returns a specific validation error for unsupported precision. Exact Uniswap v3 TickMath/Q64.96, fee growth and future execution remain out of scope.

`python3 scripts/audit/ao-concentrated-reference.py` independently swept 162 accepted cases across six narrow/wide/small/large ranges, three prices per range and four decimal pairs. Worst observed absolute root error was 9.995×10^-19. Worst token0 absolute error was 893.927 token0 units in a tiny-price case where the modeled token0 amount was enormous; worst relative token0 error was 4.363×10^-9. Worst token1 absolute error was 0.000001501 token1; worst relative token1 error was 2.25×10^-9. Worst token1-denominated value error was 1 unit on a roughly billion-unit position; worst relative value error was 2.221×10^-9. These are **observed corpus maxima**, not formal worst-case bounds over all supported inputs. Each active token's raw-unit floor is separately bounded to at most 0.01% of modeled value by the new guard. Golden vectors in `tests/am-math.test.ts` compare against independently computed continuous values and reject both catastrophic cases. The mathematically exact reference Pa=.25, Pb=4, L=100 still gives 50/50 initial tokens, 150 token1 LP versus 250 HODL at upper price, and −40% divergence.

## Adversarial text and browser boundaries

The static ABI decoder now rejects high address padding, boolean words other than 0/1, unsigned high bits, signed sign-extension errors and fixed-byte trailing padding before presenting decoded values. It already bounds ABI JSON to 8 KiB, calldata to 4 KiB, at most eight static function fragments/eight inputs, exact selector matching and exact calldata length; tuples, arrays and dynamic data remain unsupported. Tests retain official EIP-55 and Ethereum Keccak vectors and reject malformed/ambiguous selectors. No remote signature database or RPC is used. ABI names and decoded values are rendered through text APIs.

The CSV parser retains its 256 KiB, 1,000-row, 30-column and 2,048-character cell bounds, strict UTF-8, quoted newlines and escaped quotes, explicit delimiter/header/mapping, exact decimal strings, UTC offset rules, duplicate conflict reports and immutable original JSON. Spreadsheet CSV export now prefixes suspicious `=`, `+`, `-`, `@` even after C1 controls, zero-width and bidi/control prefixes; exact machine-readable JSON is not altered. Quoting alone is not claimed as formula protection. No Taxlot schema or storage path is involved.

Chromium and Firefox local-catalogue tests visited all 20 pure-local pages with external and same-origin API requests blocked, and wallet, IndexedDB and Web Storage probes installed. No forbidden request or call and no page runtime error occurred on page load. Existing focused browser tests exercise samples, mode changes, local downloads and invalid input. This evidence is browser-local and does not prove authenticated hosted QA.

## Frozen beta and CSP

The reviewed beta package remains exactly eleven files, SHA-256 `f2907ac694594531e16ab5501e3be7d066edf98f528553f2bf2164dde725a425`. Its eight pages contain four distinct executable inline scripts. The HTTP CSP declares their four hashes **plus six historical surplus hashes**. This unnecessarily enlarges the set of script bytes CSP would permit if injected; it is a beta reapproval item, not an observed script injection. AO now rejects any new, unreviewed surplus hash while preserving the existing package bytes. Removing the six would change the frozen package and requires separate review. `connect-src 'none'`, `frame-ancestors 'none'`, noindex and the rest of the reviewed response policy remain intact in the local host-package configuration.

The beta build now aliases shared `global.css` imports to a checked-in immutable copy of the reviewed 13,828-byte CSS (`src/read-only-beta/frozen.css`). Unrelated source and audit prose cannot be scanned into this beta stylesheet. `node scripts/release/beta-css-isolation.mjs` creates a disposable unimported source fixture containing valid Tailwind utility tokens, rebuilds the beta, verifies every package file and exact package SHA, checks that the injected utilities are absent, and removes the fixture. This is included in the final release gate. The full application still uses the original stylesheet and its existing utilities. Tailwind's [official source-detection documentation](https://tailwindcss.com/docs/detecting-classes-in-source-files) confirms that automatic scanning treats project source as plain text and that `source(none)`/explicit sources are available; immutable reviewed CSS is the narrower choice for this already-deployed beta.

Static artifact guards cover noindex, CSP hashes, secrets, source maps, mainnet endpoints, analytics dependencies and unauthorized external executable assets. Hosted authenticated HTTP checks remain **NOT VERIFIED**; no browser session, bypass credential or deployment operation was used.
