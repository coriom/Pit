## Readiness architecture

`src/lib/operator-readiness.ts` defines typed `PASS`, `FAIL` and `UNKNOWN` checklist rows for both protocols. `ReadinessPanel` renders the rows without calling a signing API. It consumes the existing `useExecutionPreflight` result; it is **an explanation of that gate, not a replacement execution authorization**. `inspectCow`/`inspectSwap` and `inspectPerp` still recheck their exact network, balances, storage and live context at the actual execution entry points. UNKNOWN never turns into GREEN. The existing preflight may make wallet-provider and protocol **read** calls, including a transient write/delete in IndexedDB's `meta` store to verify storage, but it creates no accounting event.

`OperatorCheckpoint` adds a separate review click and required checkbox before calling the existing CoW approval, CoW SDK sign-and-submit, or Hyperliquid order function. The SDK's CoW signature and submission remain one existing operation; the checkpoint names both and the external wallet independently asks the operator to approve its prompt. Every new reduce-only close gets its own Hyperliquid checkpoint. Changing account, chain, assets, amount, quote, market, side, price, size, or reduce-only resets the relevant checkpoint. The real continuation is disabled unless the existing gate is GREEN and the operator checks the review box. The execution function then rechecks preflight. No signing/order construction or fee calculation changed.

Dry run is an explicit local UI mode. It previews the approval and order checkpoints but branches to state transitions before any wallet approval/signature/submission function is called. It can be rehearsed while disconnected, showing FAIL/UNKNOWN rows; it cannot clear the real gate. The Playwright test completed both CoW previews and a Hyperliquid order preview with **zero** `eth_requestAccounts`, sign/send RPC calls, exchange/order HTTP requests, and zero PIT IndexedDB databases. The checkpoint continuation was disabled until the review checkbox was checked. The existing direct execution tests and quote provenance tests remain part of `pnpm release:check`.

## Operator sequence and evidence to capture

1. From a clean checkout, run `pnpm release:check`. Confirm `FEES_ENABLED=false`, `MAINNET_ENABLED=false`, the intended exact testnet endpoints and an approved accounting origin. A local loopback rehearsal does **not** close Assumption 8 or establish public HTTPS header behavior.
2. Connect only the external wallet/provider. For CoW, verify the wallet itself reports Ethereum Sepolia **11155111**, actual public account, exact sell/buy ERC-20 addresses and balances, and enough Sepolia ETH. For Hyperliquid, verify the distinct testnet-funded account, exact testnet API, available collateral, market and position. Do not provide PIT a key or credential.
3. Optionally turn on dry run and rehearse every checkpoint. It only advances the UI; switch it off before a separately authorized live session. A successful diagnostic market read is **not** an executable quote. A quote-comparison display object, copied object, forged label, stale object or different wallet/request cannot enter the private CoW execution map. Only a fresh `quoteSwap` result can; `inspectSwap` is run again at approval and submission.
4. Request the wallet-bound CoW quote. Wait for all mandatory readiness rows and the existing gate to be GREEN. Inspect protocol, chain, account, exact asset addresses, sell amount, SDK helper-derived spot price, protocol fee, solver network cost, partner fee **0**, minimum receive, wallet gas as separate/unknown, and Taxlot `trade` only **after a confirmed fill**. Click the **token approval** checkpoint, read its values, check the review box, then explicitly approve or reject the external-wallet token approval prompt. If allowance is already sufficient, the existing approval function makes no approval transaction; do not infer a transaction occurred from clicking.
5. Recheck the fresh quote and exact details. Click the separate **order signature and submission** checkpoint, check the review box, inspect the EIP-712 domain, settlement, assets, amounts and appData in the external wallet, then explicitly approve/reject that wallet prompt. The existing SDK sign-and-submit call is one operation; no automatic confirmation or retry occurs. Submission is not settlement.
6. For a separately authorized minimal Hyperliquid testnet order, wait for GREEN. Inspect market, side, size, limit price, reduce-only, unknown exchange fee, PIT fee **0**, and raw-only derivative accounting. Click the **order** checkpoint, check the review box, then explicitly approve/reject the wallet prompt. If closing exposure is required, select reduce-only and repeat a **new position-close checkpoint** and wallet confirmation. Do not call a resting order a fill.
7. Capture CoW account/chain/tokens, submitted order UID, settlement transaction hash, final status and exact executed sell/buy/fees from the Sepolia orderbook and explorer. Verify PIT partner fee stayed zero. For every confirmed crypto-to-crypto fill, verify the locally stored Taxlot v1 `trade` against the upstream schema, then reconcile on-chain/API quantities → IndexedDB event → CSV row field by field. Capture timestamps and differences; an unfilled order creates no trade event.
8. Capture Hyperliquid account, market, side, size, order/fill identifier, submitted builder fields (absent), fee, funding if any, terminal order/position state and raw `unsupported_derivative_v1` evidence. Verify no Hyperliquid fill became a spot Taxlot event or CSV row. Preserve any unresolved discrepancy as a blocker.

Stop on a FAIL/UNKNOWN mandatory fact, a changed wallet/quote, unexpected signature request, missing fill, unknown accounting origin, or reconciliation mismatch. No current Phase T evidence substitutes for those future live records.
