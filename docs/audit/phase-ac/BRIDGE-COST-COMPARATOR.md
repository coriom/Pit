# Phase AC — Bridge Cost Comparator

**Scope:** `/tools/bridge-cost/` is a browser-local, scenario-based calculator for hypothetical Ethereum Sepolia (11155111), Base Sepolia (84532) and Arbitrum Sepolia (421614) routes. Those chain labels do not establish actual bridge availability. The sample source/destination addresses are explicitly fictional placeholders. No bridge SDK, RPC, quote API, backend, wallet connection, signature, approval, transaction, Taxlot event or IndexedDB write is involved. `FEES_ENABLED=false`, `MAINNET_ENABLED=false`, `UNISWAP_EXECUTION_ACCEPTED=false`, noindex, Assumption 8 OPEN and legal gates remain unchanged.

## Difference from Phase AB

Phase AB estimates a same-chain swap's quoted output, embedded fees, wallet gas and slippage. Phase AC requires **different source and destination chains**, exact chain/address/decimal token identities, a common gross source-token transfer budget, five fee categories with payer/chain/denomination/coverage, two independent native-gas obligations, an optional claim fee and intermediate-swap fee, optional minimum destination amount, optional completion time and optional common valuation unit. A token ticker never establishes equivalence. The engine reuses only Phase AB's exact decimal parser and raw-unit formatter; it does not turn swap quotes or executable intents into bridge scenarios.

## Exact calculation contract

Each nonzero manual amount is parsed to `BigInt` base units using explicit decimals (0–36), with `uint256` input bounds and no floating-point intermediary. Conversion rates are explicit positive decimal rationals with up to 18 fractional places. For a fee of `F_raw` in asset `X` with `d_X` decimals, a rate of `R_scaled` destination tokens per whole X, and destination decimals `d_D`, the conservative separate cost is:

`ceil(F_raw × R_scaled × 10^d_D / (10^d_X × 10^18))` destination-token raw units.

Source and destination native costs are computed independently: `source gas wei = (source wallet gas units + required approval gas units) × source gas price in wei`; `destination gas wei = destination wallet gas units × destination gas price in wei`. Each is converted using **its own chain-scoped native-asset identity and explicit rate**. Raw gas wei from different chains are never added. If destination gas is marked included/relayer-covered, its wallet obligation is zero; unknown coverage is not zero. Approval `NO` contributes zero gas; `YES` requires units/price/rate; `UNKNOWN` blocks complete economics.

The manually entered destination quote is defined **after embedded fees and before separate fees**. Included bridge, LP, relayer, claim or intermediate-swap fees are reported with their raw amount and payer, never deducted again. Separate destination-proceeds fees reduce actual destination tokens received. Separate external wallet fees are converted to destination-token economic cost; relayer-paid separate fees are reported but do not charge the wallet. An included fee cannot be labelled wallet-paid. A destination-proceeds fee must be destination-token denominated. `expected received = quote − separate payout fees`; `total separate user cost = payout fees + converted external wallet fees + converted source/approval gas + converted destination gas`; `effective net destination value = quote − total separate user cost`. Net value may be negative. PIT fee is exactly zero.

The optional minimum is a manually supplied floor on the quote **before** separate payout fees; it must not exceed the quote or fall below those payout fees. The displayed minimum after payout and net-minimum scenario subtract those fees and wallet costs separately. It is not a guarantee by PIT. Optional time is displayed in minutes and never enters financial ranking. A manually named common valuation unit has explicit decimals and destination-to-common rate; it reports cost and net separately from destination-token units. Converted positive costs round upward; a positive common-unit net display rounds downward; raw destination results remain exact.

## Comparison coverage

Two scenarios rank only when both have complete fee, approval, gas and conversion coverage and exactly match source/destination chain, token address and decimals, gross source-token transfer budget, native-gas asset identities, active conversion assumptions and optional common-unit assumptions. Missing/unknown data or a mismatch yields **`NOT COMPARABLE — incomplete or incompatible route economics`** without a winner. A complete pair uses **`Best estimated net destination value under supplied assumptions`**. It reports the absolute net difference, separate-user-cost difference and that cost difference as a percentage of the higher separate cost, backed by exact numerator/denominator raw integers. The gross source transfer budget excludes separately disclosed external wallet gas/fees; those are normalized to destination value in the comparison. A route's manually supplied destination quote must correspond to its stated source transfer amount; PIT cannot verify this offline.

## Privacy, limits and release evidence

The registry-driven page uses a deterministic CSP-hashed inline script and a browser-local JSON Blob download. The report contains manual route inputs, all fee assumptions and raw results, coverage/comparability status, `pit.bridge-cost.simulation.v1` and a simulated-only disclaimer. The built-browser test blocks all external HTTP, spies on wallet-provider methods and IndexedDB opens, and verifies both counts remain zero. Static artifact/discoverability checks ensure local pages have no wallet or protocol JS chunk, no remote executable script and noindex. The Token Approval Inspector link is registry-provided and covers only four reviewed Sepolia pairs.

The calculator does **not** verify canonical issuance, wrapping/redeemability, token contract code, bridge smart-contract security, liquidity, transfer minimums/maximums, finality, refunds, failure costs, dynamic gas, cross-chain price changes, MEV or tax treatment. Even identical token symbols or matching manually entered rates do not prove economic equivalence. LI.FI Intents, Across and other network integrations remain separately reviewed future candidates; none was added here. No live quote is requested because this phase is deliberately an offline scenario tool, not a bridge availability or execution service.
