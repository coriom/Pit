# PIT V2 Phase 8 — integrated local product and payment readiness

## Product boundary

The unified loopback preview is assembled with `pnpm product:preview:build` then `pnpm product:preview:serve` at `http://127.0.0.1:4414/`. It presents 151 offline Toolbox experiences, 28 Explorer inspections and 18 Operations routes from their existing registries. The 197 routes represent 196 distinct tasks; the preview does not invent another tool. This local static compositor serves independently checked artifacts and their respective CSPs. The Toolbox remains a zero-JavaScript, `connect-src 'none'` build. Explorer reads are manually initiated and can reveal submitted addresses to its fixed RPC providers. Operations signing remains limited to local Anvil 31337. The guide at `/guide/` explains the user boundaries. The separate hosted builds are unchanged in purpose; no public unified host or paid service is deployed.

The directory filters category, search text, usage, network and price. It initially shows 24 cards to keep the page navigable and expands or filters without fetching from PIT servers. Existing deep links remain valid. The Operations guide and detail pages disclose network, wallet, fee and risk status. The standalone free Toolbox still has its own homepage and search; it does not import wallet or payment JavaScript. Existing free-page titles and descriptions remain; canonicals and a sitemap are generated only when a separately approved HTTPS public origin passes the legal-information gate. Private Operations and Explorer packages remain noindex. No production indexing or publication was enabled.

## Pricing and payment

The source of provisional prices is `src/lib/pit-pricing.ts`. Fixed local mock-USDC fees are 49 for standard ERC-20 creation, 149 for advanced creation, 39 for lock creation and 79 for vesting creation. ERC-20 MultiSender costs 3 + 0.10 per recipient, capped at 49. NFT and other operation prices remain indicative only. Free reads, calculations, allowance revocations and claims are not paywalled. There is no subscription, account, credit balance, merchant checkout or live USDC payment in this V2 model.

The optional `?paid-local=1` flow on four existing operation pages covers five paid actions: configure, on-chain price/version quote, exact local mock-USDC and asset approval, simulation, Anvil wallet confirmation, receipt/event validation, contract state readback and JSON receipt export. It displays service fee in six-decimal mock-USDC and estimated gas in native ETH separately. It names payer, fee recipient, spender, destination, asset movement, intent, maximum fee and expiry. The contract checks version, deadline, max fee and a unique per-payer/router intent. It transfers the fee directly to an immutable recipient using SafeERC20 and checks exact payer/recipient balance deltas. A failed atomic operation rolls back fee and intent state. Separate approval gas and reverted transaction gas are not refunded. A pending hash blocks automatic resubmission; canonical-block and event reconciliation precede a success state. A page refresh can leave state readback unverified, which is reported honestly.

Permissionless contracts or equivalent code remain callable outside PIT's paid guided route. The merchant address in the local fixture is not a live payout wallet. An immutable recipient limits admin abuse but demands exact ownership and configuration review before deployment; a wrong address requires replacement contracts. The owner can update prices, incrementing the version and invalidating old quotes. There is no emergency pause; replacing/disabling a client route cannot prevent direct calls to an already deployed router. No independent security audit has been performed.

## Base Sepolia preflight, read-only

[Circle's current testnet address table](https://developers.circle.com/stablecoins/usdc-contract-addresses) lists Base Sepolia test USDC at `0x036CbD53842c5426634e7929541eC2318f3dCF7e`. Circle states testnet tokens have no financial value. [Base's current network table](https://docs.base.org/get-started/connect-to-base) lists official read-only RPC `https://sepolia.base.org` and chain ID 84532. The reproducible `pnpm operations:payment:preflight` script uses only `eth_chainId`, `eth_blockNumber`, `eth_getCode`, `eth_call` and `eth_feeHistory`; it has no signer or write method. On 2026-10-28 it observed chain 84532, block 51,346,806, code hash `0xedc5281a85c0efecd49999a1ef668390c59b88702f2d4a07029d7f5d63059d6c`, name/symbol `USDC`, six decimals, successful `allowance` and `balanceOf` reads, fee-history support, and matching code hashes for the six existing PIT contracts in `deployments/base-sepolia.json`. No transfer, approval or EIP-3009 behavior was tested on public testnet. Node fetch timed out in this WSL environment; a single curl chain-ID probe worked and the bounded curl-based read-only script completed. This is ABI/read compatibility evidence, not funded payment or fork-settlement acceptance.

`deployments/base-sepolia-paid-candidate.json` is a **non-deployable** reviewed-source/bytecode candidate for exactly two routers, `PitPaidTokenCreator` and `PitPaidOperations`. It records Solidity 0.8.24, optimizer 200, OpenZeppelin 5.5.0, source SHA-256, creation-code and runtime-template hashes, constructor shape, Circle-listed test token and provisional micro-unit prices. The runtime template hash is **not** a claim about a deployed address because constructor immutables are inserted at deployment. Fee recipient and price administrator are deliberately null; no actual deployment address exists. `pnpm operations:payment:manifest:check` fails if the committed manifest diverges from compiled source.

Local Anvil paid-operation gas measurements from Phase 7 were 580,775 standard creation, 1,588,041 advanced creation, 157,209 two-recipient MultiSender, 677,115 lock creation/funding and 872,734 vesting creation/funding. Current local acceptance measured 3,895,646 gas for PitPaidTokenCreator deployment and 3,445,729 gas for PitPaidOperations deployment. The local mock-USDC deployment used 547,350 gas and is not needed on Base Sepolia because the Circle-listed test token already exists. These units are not live Base gas quotes; L2 fee components and current gas prices must be measured before a bounded testnet approval. The prospective testnet campaign needs two router deployments, exact-USDC approvals and selected low-value test operations. Its maximum transaction count, per-transaction gas price and aggregate test-ETH budget remain unset until the verified signer, recipient, funding source, test amounts and current fees are known. No arbitrary default budget is safe.

## Reports and commercial activation

The Portfolio Batch Risk and Trading Journal Advanced engines are real server-side local report engines. The x402-shaped portfolio demo still has `X402_SETTLEMENT = SIMULATED`: local fixture authorization, verification and settlement, no official SDK or real facilitator, no certified interoperability and no real sale. No hosted paid-report route is enabled. Financial imports are not retained by the demo; a later hosted design requires an explicit privacy notice, request limits, verified settlement, operation-bound result delivery and a refund policy. Historical Premium subscription and credit infrastructure is retained but not used by PIT V2 Operations.

A controlled Base Sepolia payment trial needs: independent verification of Circle token code and supported behavior at the trial block; merchant recipient ownership proof and business/legal configuration; administrator and price-change governance; external contract review; public bytecode/source verification; explicit signer, recipient, amount, gas and transaction budget approval; on-chain event/receipt reconciliation with reorganization handling; support, refund, tax and accounting records; reviewed consumer terms and privacy notice. On-chain logs can support technical reconciliation but do not alone establish legally sufficient record retention. No retention period or regulatory approval is asserted. Mainnet and commercial launch require separate decisions and acceptance.

**Current status:** local integrated preview and mock-USDC payment prototype only. No Base Sepolia payment router deployment, real transfer, public hosting, Sourcify submission, production fee collection or independent audit. Manual MetaMask extension acceptance is deferred until final pre-launch validation.
