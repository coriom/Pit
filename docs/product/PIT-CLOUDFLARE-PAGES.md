# PIT Toolbox Cloudflare Pages Direct Upload preparation

Status: **local package only; no Cloudflare account, project or deployment was created**. The existing protected Vercel Production is unchanged. The default package is private-intent (`noindex,nofollow`) but **noindex is not access control**: a future `pages.dev` upload would be publicly reachable immediately.

## Host fit and cost, checked 2026-10-22

The 119-task PIT Toolbox is static HTML/CSS with approved inline scripts. It needs no Pages Functions, Workers, database, external API or paid Cloudflare service. Cloudflare says static Pages asset requests are free and unlimited on Free and paid plans. The Free limits are 20,000 files per site, 25 MiB per file and 500 builds/deployments per month; this package has 141 files and its build guard rejects files over 25 MiB. One `_headers` rule is used, below Cloudflare's 100-rule ceiling, and the longest line is checked against its 2,000-character limit. Sources: [static request pricing](https://developers.cloudflare.com/pages/functions/pricing/), [Pages Free limits](https://developers.cloudflare.com/pages/platform/limits/), [custom headers](https://developers.cloudflare.com/pages/configuration/headers/).

Cloudflare's [pricing page](https://www.cloudflare.com/plans/) describes its $0 Free plan as suited to personal or hobby projects that are not business-critical. The reviewed [Developer Platform terms](https://www.cloudflare.com/service-specific-terms-developer-platform/) did not establish an explicit Pages Free commercial-use prohibition, but this is not enough to promise suitability for PIT's still-undecided professional/commercial operating model. Confirm the actual account agreement and intended use before a commercial launch. A fallback is [Netlify Free](https://www.netlify.com/blog/introducing-netlify-free-plan/), whose own material expressly permits commercial projects; its current [pricing](https://www.netlify.com/pricing/) has a hard 300-credit monthly limit and pauses sites at that limit rather than charging. Neither provider is guaranteed to remain free or continuously available. No fallback package or account was created.

## Package and security boundary

Run `pnpm toolbox:cloudflare:check` to build `dist-local-toolbox-cloudflare/`. The command validates the existing isolated Vercel source package, copies only its 139 reviewed static files, then adds exactly `_headers` and a top-level `404.html`. There are 137 content HTML pages (home, catalogue, privacy, legal, 20 workspaces and 113 task URLs) **plus one 404 error document**. The 404 is required because [Cloudflare Pages otherwise treats a site without one as a single-page app and may return the homepage for unknown routes](https://developers.cloudflare.com/pages/configuration/serving-pages/). No Functions, `_worker.js`, rewrites, executable bundles or Git integration files are uploaded.

The single `/*` header rule carries the same exact-script-hash CSP as the reviewed source: `connect-src 'none'`, `form-action 'none'`, `frame-ancestors 'none'`, and no external script permissions. It also carries HSTS (`max-age=86400`, no preload or subdomain inheritance), `nosniff`, `no-referrer`, `DENY` framing, restricted permissions and private `X-Robots-Tag: noindex, nofollow`. The package validator compares every copied byte to the guarded source, rejects unexpected files or altered headers, enforces Free limits and computes a deterministic SHA-256 over the complete package. `_headers` is configuration; only a future hosted HTTP response can prove Cloudflare applied it.

The existing public-build gate remains separate. A future public build needs completed publisher/privacy notices, `PIT_TOOLBOX_PUBLIC_RELEASE_APPROVED=yes`, and the exact approved `PIT_TOOLBOX_PUBLIC_ORIGIN=https://<assigned-name>.pages.dev`. Only then can `pnpm toolbox:cloudflare:public:check` produce `dist-local-toolbox-cloudflare-public/` with approved canonical URLs, sitemap and indexing. The default command cannot enable indexing. Do not upload a noindex candidate as if it were private.

## Later operator-authorized Direct Upload, not executed here

1. Confirm the real publisher/contact/jurisdiction information in [PIT-PUBLICATION-FACTS.md](./PIT-PUBLICATION-FACTS.md), the Cloudflare account's Free plan and actual agreement, and separate authorization to make a `pages.dev` site publicly reachable. Obtain or create a Cloudflare account; no custom domain or card is needed for the static Pages Free proposal. Review the assigned hostname before building public canonical URLs.
2. With explicit approval, authenticate Wrangler as the operator, then create **one Direct Upload Pages project**, without Git integration: `pnpm dlx wrangler@4 pages project create <approved-project-name> --production-branch main`. Read back the actual `<assigned-name>.pages.dev` hostname; Cloudflare may add characters if the name is taken. [Cloudflare Direct Upload guide](https://developers.cloudflare.com/pages/get-started/direct-upload/).
3. Once the legal pages contain approved facts and the exact hostname is known, set the two public-build variables above, run `pnpm toolbox:cloudflare:public:check`, review its SHA-256 and inventory, then deploy **only** the output directory with `pnpm dlx wrangler@4 pages deploy dist-local-toolbox-cloudflare-public --project-name <confirmed-project-name> --branch main --commit-hash <reviewed-sha>`. Do not use repository-root upload or connect Git. [Wrangler Pages commands](https://developers.cloudflare.com/workers/wrangler/commands/pages/).
4. After any separately authorized upload, verify actual HTTPS responses, all 137 content routes, excluded-route HTTP 404s, CSP/security headers, browser-local calculations and downloads, no external requests, and actual indexing policy. The current local test is not hosted evidence.
