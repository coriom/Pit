# Manual publication

1. Run `scripts/deploy.sh build`, then `pnpm test:e2e`. Review `dist/build-manifest.json`, fee flags, legal pages, and evidence. Keep the artifact unchanged between verification and upload.
2. Current testnet staging target: a dedicated, Vercel-Authentication-protected Vercel project. A repository-root Git build uses the versioned root `vercel.json` with `outputDirectory: "dist"`; `pnpm release:check` rejects it if its CSP hashes or security headers differ from the generated build. For a direct static API upload, build locally with `pnpm build` and upload the **contents of `dist`** at the deployment root, including generated `dist/vercel.json` as root `vercel.json` (not `src/vercel.json`). Confirm from an authorized application HTTP 200 that Vercel actually applied the CSP and security headers before approving the exact origin for accounting. The former Cloudflare workflow remains available as a manual alternative: authenticate Wrangler locally (`pnpm dlx wrangler@4 login`) and use `PIT_CF_PROJECT=your-project scripts/deploy.sh cloudflare`. Keep credentials operator-side only.
3. IPFS: install Kubo and run your own node. `scripts/deploy.sh ipfs` adds and pins the static directory locally, printing its CID. Local pinning requires the node to stay reachable. For durable public availability, replicate that CID to another operated node or a pinning service using its operator UI. Keep service credentials outside this repo/browser bundle.
4. Accounting requires an exclusively PIT-controlled, explicitly approved HTTPS origin in `src/lib/storage-origins.ts` before building. The default list is empty. Use a dedicated Pages/custom domain, DNSLink origin or stable dedicated IPNS subdomain; no wildcard gateway approval. Shared `/ipfs/<CID>/` and `/ipns/<name>/` paths are prohibited for production and must show disabled accounting/export. Direct immutable CID subdomains remain accounting-disabled to avoid self-CID allowlist circularity. Verify the canonical final origin, exclusive hosting control, HTTP headers, wallet/UI behavior and artifact manifest. See [Phase G origin invariant and approval requirements](audit/phase-g/ORIGIN-ISOLATION.md).
5. ENS: `scripts/deploy.sh ens` prints instructions only. In a trusted ENS manager, connect the name owner's wallet and set the resolver's contenthash to `ipfs://<verified CID>`. Inspect and sign the transaction manually. Verify resolver readback and website resolution. Retain the prior CID for rollback.

Never enable fees as a side effect of deployment. Fee recipients, builder approval behavior, mainnet guards and counsel's opinion require a separately reviewed release.

References: [Cloudflare direct upload](https://developers.cloudflare.com/pages/get-started/direct-upload/), [Wrangler Pages commands](https://developers.cloudflare.com/workers/wrangler/commands/pages/), [IPFS pinning](https://docs.ipfs.tech/how-to/pin-files/), [ENS contenthash](https://docs.ens.domains/ensip/7/).


## Dedicated testnet staging gate

Use the protected PIT Vercel testnet staging project and its exact stable HTTPS alias. [Phase Y.1's staging evidence](audit/phase-y/VERCEL-STAGING.md) and [Phase K's acceptance criteria](audit/phase-k/DEDICATED-ORIGIN.md) require actual application HTTP response headers, not merely a generated meta CSP or Vercel Authentication redirect. `pnpm build` derives `dist/vercel.json` and `dist/_headers` from Astro's page CSP, including `frame-ancestors 'none'`. No origin is auto-approved: verify project ownership, isolation, response headers, browser storage, reload persistence and CSV first; then review adding only the exact stable host to `accountingOrigins`. Keep SSO enabled. `pnpm staging:smoke` still needs a reviewed origin and a real shared IPFS/IPNS path URL for negative evidence. Keep production domains, ENS and other projects untouched.
