## Routing and authentication

Compose requires explicit `PIT_API_HOSTNAME`, `PIT_PROXY_NETWORK` and `PIT_TLS_RESOLVER`. Only `pit-api` joins that reviewed existing proxy network and carries a Traefik router, restricted to `Host(<approved hostname>) && PathPrefix(/pit/api/v1/)`, `websecure`, TLS and port 8789. It preserves the prefix; no stripping middleware is configured. Worker, migration and database retain `traefik.enable=false` and have no published ports. The operator-supplied HBI route uses the IP host plus `/hbi`; Toolio uses another hostname. A dedicated PIT hostname avoids a planned Host-rule collision, but actual Coolify-generated labels, network attachments and router precedence must be checked before deployment. The current SSH account still cannot read Docker network names without privilege; no additional broad inventory was attempted.

The planned Cloudflare gateway validates Access JWT identity, signs each request with a server-only HMAC, and the origin atomically consumes one-time nonces. Direct unsigned origin requests fail in local tests. Invitation quotas, capability-scoped private reads and bounded API concurrency (32 active requests, then HTTP 503 with `Retry-After`) are enforced locally. A discovered worker failure-path defect that persisted `status` and `error_code` in reverse order was corrected and covered by a regression test. The gateway is not deployed. Cloudflare Worker `fetch()` cannot target the VPS IP literal, and the current certificate covers only that IP. A controlled DNS hostname, a trusted certificate for that hostname, exact Access policy and hosted bypass tests remain prerequisites. No browser bundle contains the HMAC key.

## Outbound boundary

An ordinary Docker bridge does not independently prevent outbound access to host/private destinations. The API and worker still need egress to fixed public RPC endpoints; the API also performs bounded RPC reads for monitor creation. The NFT checker accepts user-controlled metadata URLs, so **production NFT metadata job creation and processing are both disabled in source and pinned to disabled in Compose**. The HTTPS-origin frontend displays a clear unavailable notice and disables its submit button; a local loopback build retains the tested workflow. This is a deliberate partial private-beta capability, not proof of network isolation. Re-enabling hosted NFT fetching requires a separately reviewed network egress control, including IPv4/IPv6, host INPUT and forwarding, DNS rebinding, redirects and public-IP hairpin, plus tests against disposable fixtures. No host firewall change was made.

## Packaging and recovery

`.github/workflows/pit-backend-image.yml` is manual-only (`workflow_dispatch`) and checks an exact `main` source SHA. It builds the digest-pinned Node image, emits a CycloneDX SBOM, scans with pinned Trivy, rejects fixable HIGH/CRITICAL findings and only then publishes a SHA-tagged GHCR image and reads back the registry digest. It has no deployment trigger or step. The local 2026-11-11 Trivy scan reported 34 HIGH and one CRITICAL finding, with zero fixed versions reported; Debian classifies the remaining MiniZip-related zlib CRITICAL as inapplicable to the Bookworm binary build. The residual findings remain visible in the workflow artifact; a successful scan gate does not mean zero vulnerabilities. Compose requires immutable image digests. If the GHCR package stays private, Coolify needs a PIT-specific pull credential supplied outside Git.

PIT PostgreSQL uses its own database, role, volume and migrations 001/002. A fresh local custom-format dump restored successfully to a second disposable PIT database; six application tables were present. A real PIT backup destination, schedule, retention, first post-deployment backup verification and image rollback digest remain rollout inputs. No neighboring database or backup schedule was touched.
