## Wallet and payment readiness

The paid local workflow now requires explicit EIP-1193 provider selection (including EIP-6963 announcements), checks the selected provider's chain, account and latest block against loopback Anvil before signing, invalidates prepared state on account/chain/disconnect events, and uses viem for simulation, exact approval, transaction, receipt and state readback. The separate Base Sepolia wallet preview requires its reviewed campaign and remains non-hosted. Browser automation uses a test EIP-1193 provider; **genuine MetaMask extension acceptance is NOT VERIFIED**. No automatic chain switching or retry after uncertain broadcast is permitted.

The live commercial configuration is intentionally absent. [`pit-production-template.json`](../../deployments/pit-production-template.json) is fail-closed and checked by `scripts/release/check-rc-config.mjs`; its merchant, chain, canonical USDC, owner, price, router and approval fields are null. Circle currently lists Base mainnet USDC as `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913` and Base Sepolia *test* USDC as `0x036CbD53842c5426634e7929541eC2318f3dCF7e` ([Circle addresses](https://developers.circle.com/stablecoins/usdc-contract-addresses)). This documentation is a reference for future independent verification, not a production address configured in the application. The test-only recipient `0xA945c984d4cD94528D0Ee3eCEe540EE66F1843B0` must never be copied into production.

The five tested service prices are proposals, centrally held in `src/lib/pit-pricing.ts`: standard ERC-20 creation 49 USDC; advanced creation 149; ERC-20 MultiSender 3 + 0.10 per recipient, capped at 49; Locker 39; Vesting 79. Gas is separately denominated in native ETH. Other NFT/native distributions have indicative metadata, not a tested paid execution route. Payment routers enforce actual prices, maximum fee, version and deadline on-chain. On-chain failed atomic execution reverts the service-fee transfer, but gas and a separate approval transaction remain spent. A successful operation is generally irreversible. Direct use of public permissionless contracts cannot be universally fee-enforced. x402 report settlement remains simulated and inactive.

## Release runbook

1. Freeze a clean source commit, dependency lock and generated package hashes. Confirm the five protected Phase CE files were untouched and no secrets are tracked.
2. Run `CI=1 pnpm release:check`, `pnpm operations:paid:test`, `pnpm operations:check`, `pnpm operations:sepolia:wallet:check`, `pnpm product:free:rc`, and targeted Chromium/Firefox wallet tests. Record every result separately. These commands build or transact only on local Anvil; no hosted deployment is implied.
3. For a possible free public release, approve a real domain/origin, review canonical URLs/robots/sitemap, configure appropriate DNS and privacy/security headers, verify public RPC capacity, publish only with separate authorization, then smoke test root, deep links, scripts, CSP and mobile views. Roll back to the previous static asset version if route, header or data leakage checks fail.
4. For the paid layer, obtain the decisions in the audit and legal packages, independently verify canonical USDC and merchant ownership, freeze production source/bytecode and contract addresses, audit and verify contracts, run bounded testnet acceptance and final real-wallet extension acceptance, then seek a separate mainnet deployment and commercial activation authorization. No automatic promotion from testnet.
5. Monitor availability, HTTP errors, public RPC failures, transaction hashes and canonical confirmations without logging imported financial data, private keys or wallet session secrets. Define an incident owner, notification path and pause/replacement process before commercial activation.

Private Cloudflare staging remains Access-protected and read-only; this source candidate is **not deployed** there. `noindex` is not access control. Workers Free/Zero Trust Free eligibility, static asset limits and any custom-domain policy require recheck before a new hosted action. The historical SIWE/D1 Premium Worker is separate from this accountless product; its source-versus-hosted divergence and protected Phase CE changes remain a separate release concern. It is not needed for free tools or on-chain pay-per-use. Keep it dormant and review a future deactivation/archive separately; do not delete schemas or modify the hosted Worker now.
